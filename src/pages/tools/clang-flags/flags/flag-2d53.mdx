## At a glance

| Attribute | Value |
| :--- | :--- |
| **Flag** | `-S` |
| **Type** | Action selection flag (Driver / CC1) |
| **Default** | Full compilation and linking pipeline (or object file generation with `-c`) |
| **Optimization levels (`-O*`)** | Independent — `-S` controls pipeline phase termination, not code optimization |
| **Primary effect** | Halts compilation phase after target code generation, emitting human-readable `.s` text assembly |

## What this flag actually does

The `-S` flag tells the Clang driver to execute preprocessing, parsing, high-level IR optimizations, target-independent code generation, and backend machine code layout, but stop immediately before calling the assembler. Instead of producing a binary object file (`.o`), Clang writes target-specific assembly code to a text file (ending in `.s` by default).

When used alongside `-emit-llvm` (i.e., `clang -S -emit-llvm`), Clang outputs target LLVM IR assembly (`.ll`) rather than native architecture assembly.

```bash
# Output native target assembly (e.g., main.s)
clang -O2 -S main.c -o main.s

# Output human-readable LLVM assembly (.ll)
clang -O2 -S -emit-llvm main.c -o main.ll
```

## How it works inside Clang

### 1. Driver pipeline phase selection

When you invoke `clang`, the driver parses arguments into an `InputArgList` and determines the target execution action phase in [`clang/lib/Driver/Driver.cpp`](https://github.com/llvm/llvm-project/blob/llvmorg-19.1.0/clang/lib/Driver/Driver.cpp#L4000). Passing `-S` sets the final compilation phase to `phases::Backend` (or `types::TY_Asm`).

```text
[ Source File (.c) ]
       │
       ▼
 [ Preprocess ] ── ( -E stops here )
       │
       ▼
 [ Parse & Semantics ] ── ( -fsyntax-only stops here )
       │
       ▼
 [ LLVM IR Opts ] ── ( -emit-llvm stops here )
       │
       ▼
 [ Target Codegen ] ── ( -S stops here -> .s text assembly )
       │
       ▼
 [ MC Assembler ] ── ( -c stops here -> .o object file )
       │
       ▼
 [ Linker ] ── ( Default binary output )
```

The driver constructs job steps up through the compilation frontend invocation (`clang -cc1`), passing `-S` or `-backend-action=emit-obj` down to the frontend action handler.

### 2. Frontend action translation

Inside the frontend driver (`clang/lib/Frontend/CompilerInvocation.cpp`), the presence of `-S` configures `FrontendOptions::ProgramAction` to `frontend::EmitAssembly` (or `frontend::EmitLLVMOnly` if combined with `-emit-llvm`).

In [`clang/lib/CodeGen/BackendUtil.cpp`](https://github.com/llvm/llvm-project/blob/llvmorg-19.1.0/clang/lib/CodeGen/BackendUtil.cpp#L1070), the code generator attaches `TargetMachine::addPassesToEmitFile` targeting `CodeGenFileType::AssemblyFile` rather than `CodeGenFileType::ObjectFile`.

### 3. Assembly generation

The backend runs target instruction selection (SelectionDAG or GlobalISel), register allocation, and frame lowering. The LLVM `AsmPrinter` pass formats instructions and directives into assembly text, writing to the specified output file or standard output.

<Callout type="info" title="Optimization Level Independence">
Verified from source: `-S` is an action-selection flag. Optimization flags (`-O0`, `-O2`, `-O3`, `-Os`) change the internal IR passes and backend instruction scheduling, but do not alter `-S` phase termination behavior.
</Callout>

## Usage example

<SourceCode
  language="cpp"
  title="example.cpp"
  code={`int compute(int x, int y) {
    return (x * 3) + (y * 7);
}`}
/>

To inspect the generated assembly for `compute`:

```bash
clang++ -O2 -S example.cpp -o example.s
```

The output file `example.s` contains the generated assembly instructions:

```assembly
compute(int, int):
    lea    eax, [rdi + rdi*2]
    lea    ecx, [rsi + rsi*8]
    sub    eax, ecx
    ret
```

## Related LLVM Optimizations & Backend Mechanisms

**Category:** Frontend Action / Codegen Termination

| Mechanism / Pass | Relationship | Details |
| :--- | :--- | :--- |
| **`TargetMachine::addPassesToEmitFile`** | Directly controlled | Configured with `CodeGenFileType::AssemblyFile` when `-S` is active. |
| **`AsmPrinter`** | Backend mechanism | Serializes machine instructions to target assembly directives and instructions. |
| **`-c`** | Related option | Stops compilation one stage later, running the MC assembler to emit binary object code (`.o`). |
| **`-emit-llvm`** | Related option | When combined with `-S`, instructs backend to emit text LLVM IR (`.ll`) instead of target machine assembly (`.s`). |

### How to verify backend assembly output

Run Clang with `-###` to inspect the exact commands executed by the driver:

```bash
clang -O2 -S test.c -###
```

The output shows `-cc1` invoked with output action settings targeting assembly emission without subsequent invocation of `llvm-mc` or `ld`.
