## What this flag actually does

`-mllvm` is Clang's global escape hatch for passing options directly to the underlying LLVM library infrastructure. Rather than mapping every internal LLVM pass parameter or debug flag into a first-class `-f*` or `-g*` Clang driver option, Clang provides `-mllvm <arg>` to append arguments directly to internal `llvm::cl::opt` option arrays.

When invoked on the Clang driver:
1. The driver collects all `-mllvm <arg>` values.
2. The driver forwards each argument as `-mllvm <arg>` to invoked child subprocesses (such as `-cc1` or `-cc1as`).
3. Inside the target process, Clang calls `llvm::cl::ParseCommandLineOptions()` using the accumulated strings to configure global or thread-local LLVM pass parameters, debug outputs, and target-backend options.

Common examples include tuning pass thresholds (`-mllvm -inline-threshold=500`), enabling debug prints (`-mllvm -debug-only=loop-vectorize`), or tweaking backend code generation (`-mllvm -x86-asm-syntax=intel`).

<Callout type="warning" title="Stability and Compatibility Risk">
Options passed via `-mllvm` are bound directly to internal LLVM `cl::opt` definitions. Unlike standard `clang` driver flags (`-f*`), these options carry **no API stability guarantees**. They can be renamed, refactored, or removed between LLVM major releases without deprecation warnings.
</Callout>

## How it works inside Clang

### Driver Forwarding
In `clang/lib/Driver/Driver.cpp`, the driver scans incoming command-line arguments for `-mllvm`. When constructing jobs (such as `clang -cc1`), the driver appends each `-mllvm <arg>` pair directly to the child process invocation arguments.

- Driver option entry in `Options.td`: [clang/include/clang/Driver/Options.td#L5294-L5296](https://github.com/llvm/llvm-project/blob/main/clang/include/clang/Driver/Options.td#L5294-L5296)
- Driver argument forwarding: [clang/lib/Driver/Driver.cpp#L2540-L2550](https://github.com/llvm/llvm-project/blob/main/clang/lib/Driver/Driver.cpp#L2540-L2550)

### Frontend Processing (`-cc1`)
When the frontend (`-cc1`) starts, `CompilerInvocation::CreateFromArgs` extracts all `-mllvm` positional parameters stored in `FrontendOptions::LLVMArgs`.

- Extraction in `CompilerInvocation`: [clang/lib/Frontend/CompilerInvocation.cpp#L1780-L1790](https://github.com/llvm/llvm-project/blob/main/clang/lib/Frontend/CompilerInvocation.cpp#L1780-L1790)
- Execution of LLVM parser: In `clang/lib/ExecutionEngine` or `CodeGen/BackendUtil.cpp`, Clang calls `llvm::cl::ParseCommandLineOptions` with `LLVMArgs`.

```
[ clang driver ] --(-mllvm -debug-only=inline)--> [ clang -cc1 ]
                                                          |
                                           FrontendOptions::LLVMArgs
                                                          |
                                    llvm::cl::ParseCommandLineOptions()
                                                          |
                                         LLVM Pass Pipeline & Backend
```

## Usage example

Passing a pass tuning parameter and a debug print filter to a C compilation unit:

<SourceCode
  language="bash"
  code={`# Pass custom inline threshold and print debug output from loop vectorizer
clang -O2 -mllvm -inline-threshold=1000 -mllvm -debug-only=loop-vectorize main.c -o main`}
/>

Examining the downstream IR/Assembly impact of `-mllvm -x86-asm-syntax=intel`:

## Related LLVM Optimizations & Backend Mechanisms

Classification: **diagnostic/frontend** (Option forwarding infrastructure).

| Pass / Mechanism | Relationship Label | Description |
| :--- | :--- | :--- |
| `llvm::cl::ParseCommandLineOptions` | Directly controlled | The core LLVM command-line parsing engine that processes forwarded string arrays. |
| `llvm::cl::opt<T>` | Directly controlled | Global or static option objects declared inside LLVM passes whose values are populated by `-mllvm`. |
| Pass Manager Pipeline | Indirectly affected | Pass parameters (e.g., vectorization factors, thresholds) modified by `-mllvm` alter pass execution decisions. |

### How to verify
To inspect how Clang forwards `-mllvm` arguments to `-cc1`, run Clang with the `-###` driver verbose flag:

```bash
clang -### -O2 -mllvm -force-vector-width=4 main.c
```

Notice the `-mllvm -force-vector-width=4` passed directly in the `-cc1` command line execution block.
