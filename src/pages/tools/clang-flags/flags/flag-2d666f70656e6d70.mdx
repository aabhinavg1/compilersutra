## What this flag actually does

The `-fopenmp` flag instructs Clang to recognize, parse, and semantically analyze `#pragma omp` directives in C/C++ source code. Without this flag, Clang treats unrecognized OpenMP directives as unknown pragmas and ignores them (emitting `-Wunknown-pragmas` warnings by default).

When `-fopenmp` is enabled, Clang executes three main pipeline transformations:
1. **Frontend Parsing & AST Creation**: Parses directives into AST nodes (e.g., `OMPParallelDirective`, `OMPForDirective`).
2. **Code Lowering (CodeGen)**: Intercepts AST nodes in `CGOpenMPRuntime` and lowers structured parallel regions into outlining calls. Lexical blocks inside directives are moved into runtime-callable microtasks (`.omp_outlined.`).
3. **Driver Linking**: Automatically appends OpenMP runtime flags (such as `-lomp` or `-lgomp` depending on toolchain target and default settings) during the link step.

To specify a non-default runtime library target (e.g., LLVM `libomp` vs. GNU `libgomp`), pass `-fopenmp-targets=` or `-fopenmp=libomp`.

Below is a parallel loop using `#pragma omp parallel for`.

    #pragma omp parallel for
    for (int i = 0; i < n; ++i) {
        data[i] *= 2.0;
    }

When compiled without `-fopenmp`, Clang ignores the directive and generates standard sequential loop code. When compiled with `-fopenmp`, Clang restructures the loop into an outlined task function and emits standard runtime dispatch calls (`__kmpc_fork_call`).

## Why use it / when not to use it

### Why use it
* **Multithreading**: Easily parallelize CPU-bound loops, reduction operations, and task queues across shared-memory architecture.
* **Target Offloading**: Paired with `-fopenmp-targets=`, enables heterogeneous offloading to GPU hardware (NVIDIA PTX, AMD HSACO).

### When not to use it
* **Single-threaded Contexts**: If multi-threading introduces unacceptable context-switching or synchronization overhead for tiny workloads.
* **Missing Runtime Support**: If linking against an embedded toolchain lacking an OpenMP runtime implementation (`libomp`).
* **Strict ABI Interfaces**: Outlining alters how internal symbols are generated; ensure exported library boundaries account for OpenMP runtime dependency initialization.

---

## Performance impact

* **Thread Overhead**: Spawning or synchronizing thread pools via `__kmpc_fork_call` carries non-zero latency. Workloads with extremely short iterations may experience performance regression unless protected by `if` clauses or schedule tuning.
* **False Sharing**: Unintended concurrent writes to adjacent memory locations within the same cache line across threads can cause hardware cache thrashing.
* **Vectorization Interference**: Outlining and dynamic scheduling calls can prevent loop vectorization unless explicit `#pragma omp simd` or `#pragma clang loop vectorize` annotations are combined.

## Compatibility table

| Driver / Frontend Option | Supported Platform | Notes |
| :--- | :--- | :--- |
| `-fopenmp` | x86-64, AArch64, RISC-V, PowerPC | Standard host parallel execution support |
| `-fopenmp=libomp` | Clang native toolchains | Default LLVM OpenMP runtime |
| `-fopenmp=libgomp` | GCC-compatible Linux toolchains | Uses GNU OpenMP runtime support library |
| `-fno-openmp` | All Targets | Disables parsing and runtime code generation |

## Usage example

```bash
# Compile and link a C++ application with LLVM OpenMP runtime
clang++ -O3 -fopenmp main.cpp -o main_omp

# Generate LLVM IR showing OpenMP outlined regions
clang++ -O2 -fopenmp -S -emit-llvm main.cpp -o main_omp.ll

# Specify target GPU offloading alongside host OpenMP
clang++ -O3 -fopenmp -fopenmp-targets=nvptx64-nvidia-cuda main.cpp -o main_gpu
```

## Adjacent options

* `-fopenmp-simd`: Enables only SIMD-related OpenMP directives without generating thread fork calls or linking `libomp`.
* `-fopenmp-targets=<targets>`: Specifies offload targets for `#pragma omp target` constructs.
* `-fno-openmp`: Completely ignores OpenMP directives in the AST stage.

## How it works inside Clang

| Pipeline Stage | Implementation Detail |
| :--- | :--- |
| **Driver** | Parses `-fopenmp`, handles runtime linking flags (`-lomp`/`-lgomp`), passes `-fopenmp` to `-cc1`. |
| **Frontend (Parser)** | ParseOMP.cpp intercepts `#pragma omp` and constructs specialized AST Nodes (`OMPExecutableDirective`). |
| **Sema** | SemaOpenMP.cpp verifies clause validity, variable capture traits (`shared`, `private`), and scope boundaries. |
| **CodeGen** | `CGOpenMPRuntime.cpp` outlines regional AST blocks into `.omp_outlined.` functions and inserts runtime API calls (`__kmpc_fork_call`). |
