## What this flag actually does

-I adds a directory to the include search list. For quoted and angle-bracket includes, the final search order also depends on the source directory, other -I options, -isystem, framework paths, and builtin or system directories. It does not link a library.

## Why use it / when not to use it

Use it when the preprocessor / include search behavior matches the build contract. Do not enable it selectively across mutually dependent translation units when it changes preprocessing, language rules, ABI expectations, or runtime instrumentation. Verify the effect with the exact compiler and target used by CI.

:::caution
This option does not repair invalid source, undefined behavior, data races, or an inconsistent build contract. It only changes the compiler mechanism described above.
:::

## Performance impact

This option is not a runtime optimizer. It does not change generated code by itself the way `-O2` or `-fvectorize` does. If a macro, include path, language mode, or warning set changes which code you build, measure **that program** with [CompilerSutraPerf](/docs/project/compilersutra-perf/) (`csperf run` / `csperf diff`) the same as any other code change. Do not treat frontend flags as free speedups.

## How it works inside Clang

### Implementation

| Stage | Source and implementation | What happens |
| --- | --- | --- |
| Options.td | [Options.td](https://github.com/llvm/llvm-project/blob/main/clang/include/clang/Options/Options.td) | Declares the include-search option and its argument form. |
| Driver parsing | [Clang.cpp](https://github.com/llvm/llvm-project/blob/main/clang/lib/Driver/ToolChains/Clang.cpp) | The driver validates and forwards user include directories to `cc1` in the include-search arguments. |
| Invocation setup | [CompilerInvocation.cpp](https://github.com/llvm/llvm-project/blob/main/clang/lib/Frontend/CompilerInvocation.cpp) | Header-search options populate `HeaderSearchOptions::UserEntries`. |
| Preprocessor | [HeaderSearch.cpp](https://github.com/llvm/llvm-project/blob/main/clang/lib/Lex/HeaderSearch.cpp) | `HeaderSearch` orders user, system, builtin, and framework search entries while resolving `#include`. |
| LLVM / backend | [Clang compilation stages](https://clang.llvm.org/docs/CommandGuide/clang.html#stage-selection-options) | After preprocessing and parsing, LLVM receives the selected token/declaration stream; it does not search headers. |
| Linker | [Clang stage selection](https://clang.llvm.org/docs/CommandGuide/clang.html#stage-selection-options) | The linker does not interpret `-I`; library search uses separate linker options such as `-L`. |

~~~mermaid
flowchart LR
 A["-I"] --> B["Options.td"] --> C["Clang driver"] --> D["CompilerInvocation"] --> E["frontend / CodeGenOptions"] --> F["LLVM IR or diagnostics"] --> G["backend / linker"]
~~~

The -I spelling is handled by the driver and translated into frontend, diagnostic, target, IR, or runtime state as shown above. LLVM and the linker consume the resulting representation; they do not generally parse the original user-facing spelling.
