## At a glance

- **Action**: Directs Clang's frontend diagnostic engine to emit warnings when language extensions outside strict ISO C / C++ standards are encountered (such as GNU C extensions, zero-length arrays, VLA extensions in C++, or binary literals in older standard modes).
- **Driver alias**: In Clang, `-pedantic` is an exact alias for `-Wpedantic`. Passing `-pedantic` forwards `-Wpedantic` to the frontend (`-cc1`).
- **Optimization level effect**: `-O0`, `-O1`, `-O2`, `-O3`, `-Os`, `-Oz`, and `-Ofast` have **no effect** on `-pedantic`. Diagnostic reporting occurs during frontend parsing and semantic analysis before IR optimization pipelines execute.
- **IR & Codegen impact**: Zero change to generated LLVM IR or target machine instructions. Valid code compiles to identical bitcode whether `-pedantic` is specified or omitted.

## What this flag actually does

The `-pedantic` flag instructs Clang to emit warning diagnostics for language extensions that are not part of the active ISO C or ISO C++ language standard revision. In the Clang driver option table, `-pedantic` is defined as an alias to `-Wpedantic`.

When code relies on compiler-specific extensions (such as GNU statement expressions `({ ... })`, zero-length array declarations in structure definitions, or non-standard pointer arithmetic on `void*`), Clang's parser and semantic analyzer (`clang::Sema`) check whether the construct is marked as an `Extension` or `ExtensionWarning` in diagnostic definitions. Under `-pedantic`, these extension diagnostics transition from silent acceptance to emitting warnings.

If paired with `-pedantic-errors` (or `-Werror=pedantic`), diagnostic warnings triggered by GNU or Clang extensions become hard compilation errors.

### Code example: GNU statement expression

<SourceCode
  language="cpp"
  code={`// GNU statement expressions are a common non-standard extension
int compute_max(int a, int b) {
    int result = ({ int _a = a; int _b = b; _a > _b ? _a : _b; });
    return result;
}`}
/>

**Compilation diagnostic behavior:**

```text
$ clang -std=c11 -c example.c
# (No warning produced by default)

$ clang -std=c11 -pedantic -c example.c
example.c:3:18: warning: use of GNU statement expression extension [-Wgnu-statement-expression]
    int result = ({ int _a = a; int _b = b; _a > _b ? _a : _b; });
                 ^
1 warning generated.
```

When evaluated, the emitted IR and assembly generated for valid compilations remain identical regardless of whether `-pedantic` was supplied on the command line.

## How it works inside Clang

1. **Driver Argument Parsing**: Clang's driver parses command-line arguments using definitions in [`clang/include/clang/Driver/Options.td`](https://github.com/llvm/llvm-project/blob/main/clang/include/clang/Driver/Options.td#L5988). The entry for `pedantic` maps directly as an alias to `W_Joined` with argument `"pedantic"`.
2. **Frontend Flag Translation**: When `clang` translates options for the `-cc1` frontend invocation in [`clang/lib/Driver/ToolChains/Clang.cpp`](https://github.com/llvm/llvm-project/blob/main/clang/lib/Driver/ToolChains/Clang.cpp#L5600), `-pedantic` is translated to `-Wpedantic` inside the diagnostic warning group processing logic.
3. **Diagnostic Engine Classification**: Inside [`clang/lib/Basic/DiagnosticIDs.cpp`](https://github.com/llvm/llvm-project/blob/main/clang/lib/Basic/DiagnosticIDs.cpp#L265), the frontend inspects the active diagnostic mappings. Diagnostics tagged with extension attributes (`CLASS_EXTENSION` in diagnostic tablegen definitions like `DiagnosticSemaKinds.td`) are evaluated by `DiagnosticIDs::getDiagnosticLevel()`.
4. **Extension Severity Upgrade**: If `-Wpedantic` is set, extension diagnostic items marked as `Extension` or `ExtWarn` have their effective severity level raised from `diag::Severity::Ignored` to `diag::Severity::Warning`.

```
Command Line: clang -pedantic src.c
       │
       ▼
Driver Options (Options.td) ── Alias to -Wpedantic
       │
       ▼
Frontend Options (-cc1) ────── Set DiagnosticGroup "pedantic"
       │
       ▼
Sema / DiagnosticIDs ──────── Elevate CLASS_EXTENSION from Ignored -> Warning
       │
       ▼
Code Generation / LLVM IR ──── Unaffected (Zero changes to AST codegen)
```

| :--- | :--- | :--- |

### How to verify
Run Clang with `-cc1` diagnostic printing flags to inspect frontend warning activation without changing target code generation:

```bash
# Observe frontend flag translation from driver
clang -pedantic -### -c main.c

# Verify IR identity with and without -pedantic
clang -O2 -S -emit-llvm main.c -o baseline.ll
clang -O2 -pedantic -S -emit-llvm main.c -o pedantic.ll
diff -u baseline.ll pedantic.ll
# Output is empty (identical LLVM IR)
```

### Source investigation
In [`clang/lib/Basic/DiagnosticIDs.cpp`](https://github.com/llvm/llvm-project/blob/main/clang/lib/Basic/DiagnosticIDs.cpp#L265), the function `getDiagnosticLevel` evaluates whether a diagnostic ID belongs to an extension group and checks the state of `DiagOpts->Pedantic` / `DiagOpts->PedanticErrors`.
