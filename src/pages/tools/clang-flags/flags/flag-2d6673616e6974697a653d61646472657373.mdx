## What this flag actually does

-fsanitize=address enables AddressSanitizer instrumentation in Clang’s frontend/codegen pipeline and links or requires the ASan runtime. It can detect many spatial and temporal memory errors at runtime, but it is not a proof of safety and does not diagnose every undefined behavior or data race.

## Why use it / when not to use it

Use it when the sanitizer / instrumentation behavior matches the build contract. Do not enable it selectively across mutually dependent translation units when it changes preprocessing, language rules, ABI expectations, or runtime instrumentation. Verify the effect with the exact compiler and target used by CI.

:::caution
This option does not repair invalid source, undefined behavior, data races, or an inconsistent build contract. It only changes the compiler mechanism described above.
:::

## Performance impact

AddressSanitizer adds shadow-memory checks, redzones, runtime initialization, and diagnostic reporting. These increase memory use and can materially slow a workload, so ASan builds are for testing, fuzzing, and debugging rather than normal production performance comparisons.

## Usage example

~~~bash
clang++ -fsanitize=address -fno-omit-frame-pointer -g example.cpp -o app
clang++ -fsanitize=address -### example.cpp -o app
~~~

## Adjacent options

Use the inverse or sibling spelling where available, and inspect the generated driver command with -###. Related controls include -O levels, -g, -I/-isystem, -D/-U, -fsanitize-recover, and target or linker options as appropriate.

## How it works inside Clang

### Implementation

| Stage | Source and implementation | What happens |
| --- | --- | --- |
| Options.td | [Options.td](https://github.com/llvm/llvm-project/blob/main/clang/include/clang/Options/Options.td) | Declares the sanitizer option group and sanitizer-kind argument. |
| Driver parsing | [Clang.cpp](https://github.com/llvm/llvm-project/blob/main/clang/lib/Driver/ToolChains/Clang.cpp) | The driver validates sanitizer kinds, forwards instrumentation settings to `cc1`, and arranges the sanitizer runtime at link time. |
| Invocation setup | [CompilerInvocation.cpp](https://github.com/llvm/llvm-project/blob/main/clang/lib/Frontend/CompilerInvocation.cpp) | Sanitizer arguments populate `LangOptions::Sanitize` and `CodeGenOptions` sanitizer state. |
| Code generation | [BackendUtil.cpp](https://github.com/llvm/llvm-project/blob/main/clang/lib/CodeGen/BackendUtil.cpp) | Clang registers sanitizer callbacks with `PassBuilder`; AddressSanitizer instrumentation and lowering passes are added to the LLVM pipeline. |
| LLVM IR / runtime | [AddressSanitizer pass](https://github.com/llvm/llvm-project/tree/main/llvm/lib/Transforms/Instrumentation/AddressSanitizer) and [compiler-rt](https://github.com/llvm/llvm-project/tree/main/compiler-rt/lib/asan) | LLVM inserts checks and shadow-memory accesses; compiler-rt provides the runtime that reports violations. |
| Linker | [SanitizerRuntime.cpp](https://github.com/llvm/llvm-project/blob/main/clang/lib/Driver/SanitizerArgs.cpp) | The driver selects and links the ASan runtime; the linker itself does not understand the sanitizer semantics. |

~~~mermaid
flowchart LR
 A["-fsanitize=address"] --> B["Options.td"] --> C["Clang driver"] --> D["CompilerInvocation"] --> E["frontend / CodeGenOptions"] --> F["LLVM IR or diagnostics"] --> G["backend / linker"]
~~~

The -fsanitize=address spelling is handled by the driver and translated into frontend, diagnostic, target, IR, or runtime state as shown above. LLVM and the linker consume the resulting representation; they do not generally parse the original user-facing spelling.

## Related LLVM Optimizations & Backend Mechanisms

**Flag category:** Instrumentation (frontend + IR + runtime). Not a classical optimization pass.

| Mechanism | Stage | Relationship | Effect |
| :--- | :--- | :--- | :--- |
| ASan instrumentation passes / checks | LLVM instrumentation | Directly controlled | Inserts shadow checks and poison/redzone logic |
| Frontend sanitizer args / ignores | Clang Driver/Frontend | Directly controlled | Enables ASan mode and related cc1 options |
| ASan runtime library | Link | Directly controlled | Links `asan` runtime |
| Frame pointer preference | Codegen interaction | Related mechanism | Stack traces often want `-fno-omit-frame-pointer` |

```bash
clang -O1 -fsanitize=address -S -emit-llvm w.c -o asan.ll

```
