## At a glance

| Property | Setting |
| :--- | :--- |
| **Driver flag** | `-ftime-report` |
| **CC1 flag** | `-ftime-report` |
| **Default state** | Disabled across all `-O` optimization levels |
| **Codegen impact** | None (emits identical machine code; pure diagnostic metadata) |
| **Phase runtime impact** | Minor wall-clock overhead due to high-precision timer calls |
| **LLVM layer** | Frontend Driver & LLVM Timer Infrastructure (`TimePassesHandler`) |

## What this flag actually does

The `-ftime-report` flag forces Clang and the underlying LLVM core libraries to instrument execution phases with high-resolution timers. When compilation completes, Clang prints a structured timing report to `stderr` detailing the CPU time (user and system) and wall-clock time spent in:

1. **Frontend Parsing & Semantic Analysis**: Header parsing, macro expansion, AST generation, and template instantiation.
2. **CodeGen (Clang IR Generation)**: Lowering Clang ASTs down to LLVM IR.
3. **LLVM Optimizer Passes**: Individual transformation and analysis passes (e.g., `InlinerPass`, `SROAPass`, `LoopVectorizePass`).
4. **Target Machine Code Generation**: Instruction selection, register allocation, scheduling, and assembly emission.

```text
===-------------------------------------------------------------------------===
                      ... Building Resource Options ...
===-------------------------------------------------------------------------===
  Total Execution Time: 0.4215 seconds (0.4218 wall clock)

   ---User Time---  --System Time--  --User+System--  ---Wall Time---  --- Name ---
   0.1240 ( 30.2%)  0.0120 ( 40.0%)  0.1360 ( 30.8%)  0.1362 ( 32.3%)  Clang front-end timer
   0.0820 ( 20.0%)  0.0050 ( 16.7%)  0.0870 ( 19.7%)  0.0871 ( 20.6%)  LLVM IR Passes
   0.2040 ( 49.8%)  0.0130 ( 43.3%)  0.2170 ( 49.2%)  0.2172 ( 51.5%)  Target Code Generation
   0.4100 (100.0%)  0.0300 (100.0%)  0.4400 (100.0%)  0.4405 (100.0%)  Total
```

### Optimization level interaction

The `-ftime-report` flag operates as an explicit user diagnostic request. Optimization levels (`-O0`, `-O1`, `-O2`, `-O3`, `-Os`, `-Oz`) do not alter the default state of this flag. 

| Optimization Level | `-ftime-report` Default State | Effect when enabled |
| :--- | :--- | :--- |
| `-O0` | Disabled | Reports frontend, AST codegen, and minimal O0 backend pipeline. |
| `-O1` | Disabled | Reports pipeline breakdown including basic inline and scalar passes. |
| `-O2` | Disabled | Reports full scalar, loop, and vectorizer pipeline breakdown. |
| `-O3` | Disabled | Reports aggressive inline, loop unroll, and vector passes. |
| `-Os` / `-Oz` | Disabled | Reports code-size optimization pass times. |

## How it works inside Clang

When `-ftime-report` is passed on the command line, the driver forwards the flag to `-cc1`. Inside the frontend and backend pipeline initialization, Clang configures LLVM's `TimerGroup` infrastructure.

```text
+-----------------------+
|  clang -ftime-report  |
+-----------+-----------+
            |
            v  (CompilerInvocation.cpp)
+-----------------------+
| FrontendOpts.TimePasses|
+-----------+-----------+
            |
            +---------------------------------+
            |                                 |
            v                                 v
+-----------------------+        +--------------------------+
|  Clang FrontEnd AST   |        |   BackendUtil.cpp        |
|  NamedRegionTimer     |        |   TimePassesHandler      |
+-----------------------+        +--------------------------+
            |                                 |
            +----------------+----------------+
                             |
                             v
               +---------------------------+
               |  LLVM TimerGroup::print   |
               |  (stderr on exit)         |
               +---------------------------+
```

### 1. Flag parsing & option propagation
In `clang/lib/Frontend/CompilerInvocation.cpp`, the parser detects `-ftime-report` and sets `FrontendOpts.TimePasses` and `CodeGenOpts.TimePasses`:

- Driver Option Definition: [`clang/include/clang/Driver/Options.td#L4180`](https://github.com/llvm/llvm-project/blob/main/clang/include/clang/Driver/Options.td#L4180)
- Parsing `TimePasses`: [`clang/lib/Frontend/CompilerInvocation.cpp#L2350`](https://github.com/llvm/llvm-project/blob/main/clang/lib/Frontend/CompilerInvocation.cpp#L2350)

### 2. Registering LLVM Pass Manager Timers
In `clang/lib/CodeGen/BackendUtil.cpp`, when constructing the LLVM pass pipeline, Clang checks `CodeGenOpts.TimePasses`. It instantiates `llvm::TimePassesHandler`, which hooks into the pass manager's execution callbacks (`registerCallbacks`):

- Backend Pass Manager Setup: [`clang/lib/CodeGen/BackendUtil.cpp#L295`](https://github.com/llvm/llvm-project/blob/main/clang/lib/CodeGen/BackendUtil.cpp#L295)

When a pass executes, the `TimePassesHandler` measures elapsed thread time and wall-clock time using OS-level high-resolution clocks (e.g., `std::chrono::steady_clock` or `getrusage`).

### 3. Destruction and Printing
Upon completion of compilation (or frontend termination), the global `llvm::TimerGroup` destructor executes (or `TimePassesHandler::print()`), writing formatted ASCII tables directly to standard error.

<Callout type="info" title="Observability vs. Output Equivalence">
Verified from source: `-ftime-report` strictly collects internal timing instrumentation. It does not modify LLVM IR transformations, instruction selection, or generated object code binaries.
</Callout>

## Related LLVM Optimizations & Backend Mechanisms

**Classification**: Diagnostic/frontend instrumentation mechanism.

| Mechanism | Relationship Label | Description |
| :--- | :--- | :--- |
| `llvm::TimePassesHandler` | Directly controlled | Handles timing measurements around PassManager pass execution events. |
| `llvm::TimerGroup` | Directly controlled | Aggregates individual timers into consolidated diagnostic timing blocks on process termination. |
| `-ftime-trace` | Related mechanism | Emits Chrome Tracing JSON format (`chrome://tracing`) instead of human-readable console tables. |

### Source investigation & verification

To observe `-ftime-report` output directly, execute Clang against any valid C/C++ translation unit:

```bash
clang++ -O2 -ftime-report -c main.cpp -o main.o
```

To verify that the flag does not affect machine code generation, run:

```bash
clang++ -O2 -c main.cpp -o main_base.o
clang++ -O2 -ftime-report -c main.cpp -o main_flag.o
cmp main_base.o main_flag.o
```

The binary comparison (`cmp`) yields no differences.
