## What this flag actually does

Clang maps -O2 to frontend and code-generation defaults and asks LLVM PassBuilder for its O2 pipeline. It enables more transformations than -O0 while avoiding some of the more expensive or code-size-heavy choices associated with -O3. It does not change C or C++ language rules: undefined behavior remains undefined.

## Why use it / when not to use it

Use it when the optimization level behavior matches the build contract. Do not enable it selectively across mutually dependent translation units when it changes preprocessing, language rules, ABI expectations, or runtime instrumentation. Verify the effect with the exact compiler and target used by CI.

:::caution
This option does not repair invalid source, undefined behavior, data races, or an inconsistent build contract. It only changes the compiler mechanism described above.
:::

## How it works inside Clang

### Implementation

| Stage | Source and implementation | What happens |
| --- | --- | --- |
| Options.td | [Options.td:254-256](https://github.com/llvm/llvm-project/blob/main/clang/include/clang/Options/Options.td#L254-L256), [845-858](https://github.com/llvm/llvm-project/blob/main/clang/include/clang/Options/Options.td#L845-L858) | Declares the optimization-level group, joined -O, -O0, -O4, bare -O, and -Ofast. TableGen emits the option identifiers used by the driver and frontend. |
| Driver parsing | [Clang.cpp:5294-5301](https://github.com/llvm/llvm-project/blob/main/clang/lib/Driver/ToolChains/Clang.cpp#L5294-L5301) | Clang::ConstructJob() takes the last OPT_O_Group argument, maps -O4 to -O3, and renders the selected optimization argument into the cc1 command. |
| Invocation setup | [CompilerInvocation.cpp:2710-2746](https://github.com/llvm/llvm-project/blob/main/clang/lib/Frontend/CompilerInvocation.cpp#L2710-L2746), [1832-1850](https://github.com/llvm/llvm-project/blob/main/clang/lib/Frontend/CompilerInvocation.cpp#L1832-L1850) | getOptimizationLevel() resolves the last spelling, treats -Os/-Oz as level 2 and -Ofast as level 3, caps unsupported numeric levels at 3, and stores the result in CodeGenOpts.OptimizationLevel. |
| Code generation | [BackendUtil.cpp:648-665](https://github.com/llvm/llvm-project/blob/main/clang/lib/CodeGen/BackendUtil.cpp#L648-L665), [1019-1022](https://github.com/llvm/llvm-project/blob/main/clang/lib/CodeGen/BackendUtil.cpp#L1019-L1022) | mapToLevel() converts Clang’s integer level to llvm::OptimizationLevel::O0 through O3; backend setup passes that level to LLVM’s pipeline builder. |
| LLVM optimization pipeline | [BackendUtil.cpp:1128-1139](https://github.com/llvm/llvm-project/blob/main/clang/lib/CodeGen/BackendUtil.cpp#L1128-L1139), [PassBuilderPipelines.cpp:622-629](https://github.com/llvm/llvm-project/blob/main/llvm/lib/Passes/PassBuilderPipelines.cpp#L622-L629) | Ordinary compilation requests PassBuilder::buildPerModuleDefaultPipeline(Level). The pipeline branches on OptimizationLevel::O2 for level-specific passes; see [1032-1041](https://github.com/llvm/llvm-project/blob/main/llvm/lib/Passes/PassBuilderPipelines.cpp#L1032-L1041). |
| LLVM backend | [TargetMachine.cpp](https://github.com/llvm/llvm-project/blob/main/llvm/lib/Target/TargetMachine.cpp) | Target-specific instruction selection, scheduling, register allocation, and emission consume optimized IR. The backend does not parse the user-facing -O2 spelling. |
| Linker | [Clang stage selection](https://clang.llvm.org/docs/CommandGuide/clang.html#stage-selection-options) | The linker combines objects and libraries after compilation. It does not select the LLVM O2 pipeline; LTO is a separate link-time path. |

~~~mermaid
flowchart LR
 A["-O2"] --> B["Options.td / TableGen"] --> C["Clang driver"] --> D["CompilerInvocation"] --> E["CodeGenOpts.OptimizationLevel = 2"] --> F["BackendUtil maps to llvm::OptimizationLevel::O2"] --> G["PassBuilder pipeline"] --> H["target backend"] --> I["object / linker"]
~~~

The option spelling is parsed by the Clang driver, converted into structured frontend/code-generation state, mapped to LLVM’s O2 pipeline, and only then lowered for the target. It is not an LLVM backend command-line option by itself.
