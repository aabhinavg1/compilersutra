## What this flag actually does

The `-mcpu=` option tells Clang and LLVM to generate machine code optimized for and restricted to a specific CPU microarchitecture. 

It acts as a dual-purpose selector:
1. **Target ISA Features**: Enables target ISA extension flags implied by that microarchitecture (equivalent to `-march=` or target features passed via `-target-feature`).
2. **Backend Machine Model / Scheduling**: Configures the LLVM Machine Instruction scheduling model (`TargetSchedModel`), pipeline hazard recognizers, register costs, and loop alignment parameters (equivalent to `-mtune=`).

### Target-Specific Semantics: x86 vs. AArch64/Arm/RISC-V

:::caution Architecture Conventions Differ
On **x86/x86_64**, GCC and Clang traditionally use `-march=` to set both ISA features and tuning parameters, while `-mtune=` overrides only the scheduling model. Passing `-mcpu=` on x86 is largely an alias or legacy option. 

Conversely, on **AArch64, Arm, RISC-V, and PowerPC**, `-mcpu=` is the primary mechanism to target a specific core implementation (e.g., `-mcpu=neoverse-v1`), while `-march=` defines abstract architecture baseline levels (e.g., `-march=armv8.4-a`).
:::

To see supported CPU names for your active target triple, pass `help` as the value:

```bash
clang --target=aarch64-linux-gnu -mcpu=help -c main.c
```

## Why use it / when not to use it

### When to use it
- **Targeted deployments**: When building binaries exclusively destined for known server fleets, edge nodes, or embedded system CPUs (e.g., AWS Graviton 3: `-mcpu=neoverse-v1`).
- **Maximum microarchitecture throughput**: When you want LLVM's Machine Instruction Scheduler to use precise pipeline latency and itinerary tables for modern execution units.
- **Enabling CPU extensions automatically**: Avoids manually listing individual target flags (e.g., `-mcpu=cortex-a710` automatically enables FP16, DotProd, Atomics, SVE, SVE2, and LSE).

### When not to use it
- **Distributing portable binaries**: Advanced `-mcpu=` selections can trap (`SIGILL`) on older cores of the same architecture family — a **portability** issue, not silent UB from the flag alone.
- **When tuning only is desired**: If you want a portable ISA baseline but prefer scheduling for one CPU, use `-mtune=<cpu>` (or the target’s equivalent) without raising the ISA floor via `-mcpu=` / `-march=`.
- **Assuming one host equals all hosts**: `-mcpu=native` (where accepted) and local CPU help output are machine-specific.

---

## Performance impact

`-mcpu=` influences code performance in two ways:

1. **Instruction Set Selection**: Allows the LLVM target lowering layer (`TargetLowering`) to materialize instructions unavailable on generic targets (e.g., hardware atomics, SIMD gather/scatter, crypto instructions).
2. **Instruction Scheduling & Costing**: LLVM's `MachineScheduler` uses the subtarget scheduling model (`MCSchedModel`) associated with the specified CPU. This alters loop unrolling factors, instruction reordering for pipeline issue slots, execution unit reservation, and vectorization cost model decisions.

:::note
If `-mcpu=` is omitted, Clang defaults to a baseline CPU model for the specified target (such as `generic` or `armv8-a`), which uses safe, minimal instruction sets and conservative scheduling assumptions.
:::

| Driver Flag | Architecture | Backend Feature Flag Translated | Notes |
| :--- | :--- | :--- | :--- |
| `-mcpu=neoverse-n1` | AArch64 | `-target-cpu neoverse-n1` | Enables LSE, RDM, DotProd, CRC, AES, SHA2 |
| `-mcpu=cortex-m4` | ARM (32-bit) | `-target-cpu cortex-m4` | Target Thumb-2 with DSP extensions |

| `-mcpu=pwr9` | PowerPC | `-target-cpu pwr9` | Enables Power ISA v3.0B instructions |

## Usage example

```bash
# 1. Inspect supported CPUs for a given architecture target
clang --target=aarch64-unknown-linux-gnu -mcpu=help

# 2. Compile for AWS Graviton 2 (Neoverse N1)
clang -O3 --target=aarch64-unknown-linux-gnu -mcpu=neoverse-n1 -c compute.c -o compute.o

# 3. Microarchitecture target with explicit feature modifier additions/subtractions
clang -O3 --target=aarch64-unknown-linux-gnu -mcpu=neoverse-v1+nosve -c compute.c
```

## Adjacent options

- **`-mtune=`**: Tunes instruction scheduling and pipeline optimization for a specific CPU microarchitecture without enabling instructions that break backward compatibility.
- **`-march=`**: Defines the target architecture profile/version and base ISA feature set (e.g., `-march=armv8.5-a`).
- **`-target` / `--target=`**: Specifies the target triple (e.g., `aarch64-linux-gnu`).

## How it works inside Clang

| Pipeline Stage | Implementation Detail |
| :--- | :--- |
| **Driver Parsing** | `clang/lib/Driver/ToolChains/Clang.cpp` extracts `-mcpu=` argument from `ArgList`. |
| **Target Feature Mapping** | `clang/lib/Driver/ToolChains/Arch/` (e.g., `AArch64.cpp`, `ARM.cpp`) resolves the CPU string into internal feature strings and appends `-target-cpu <cpu>` to CC1 options. |
| **LLVM IR Translation** | `clang/lib/CodeGen/TargetInfo.cpp` attaches `"target-cpu"="<cpu>"` function attributes to emitted LLVM IR functions. |
| **LLVM Backend** | `llvm/lib/Target/<Arch>/` uses `<Arch>Subtarget` and `MCSubtargetInfo` to initialize target instruction info, register info, and `MCSchedModel`. |

**Flag category:** Backend CPU selection (esp. non-x86 and some targets). **No direct IR opt pass.**

| Mechanism | Stage | Relationship | Effect |
| :--- | :--- | :--- | :--- |
| Target CPU selection | Driver → TargetMachine | Directly controlled | Sets CPU for ISel/scheduling |
| Scheduling / latencies | Machine backend | Backend mechanism | CPU-specific itineraries / sched models |

```bash
clang -### -mcpu=generic -c w.c 2>&1 | rg mcpu\|target-cpu
clang -O2 -mcpu=generic -S -emit-llvm w.c -o w.ll
rg 'target-cpu' w.ll
```
