| **Pipeline Layer** | Driver → CC1 (`CodeGenOptions`) → LLVM PassBuilder (`LoopUnrollPass`) |

| **CC1 Option** | `-funroll-loops` / `-fno-unroll-loops` |
| **Observability & Debug Risk** | Low correctness risk; increases code size, potentially impacting I-cache; changes loop iteration structure in step execution |

## What this flag actually does

The `-funroll-loops` flag requests that the Clang compiler enable aggressive unrolling of loops during middle-end optimization.

When passed to the Clang driver:
1. The driver parses `-funroll-loops` and translates it into `-backend-option -unroll-threshold=...` or sets `CodeGenOptions::UnrollLoops = 1` during the CC1 invocation.
2. In LLVM's `PassBuilder`, `LoopUnrollPass` and `LoopFullUnrollPass` inspect this option flag via `TargetTransformInfo` (TTI) and `LoopAnalysisManager`.
3. If loop trip counts are known at compile time (or bounded within cost heuristics), the loop body is duplicated multiple times, reducing loop branch overhead and expanding opportunities for instruction-level parallelism (ILP) and scalar replacement.

### Defaults & Multi-Level Interaction

* **`-O0`**: Loop unrolling is disabled entirely regardless of `-funroll-loops`.
* **`-O1`**: Loop unrolling is usually disabled unless explicitly requested via `-funroll-loops` (subject to cost thresholds).
* **`-O2` / `-O3`**: Loop unrolling heuristics are enabled by default for full and partial unrolling when beneficial. Specifying `-funroll-loops` explicitly sets `UnrollLoops = true`, overriding conservative cost metrics.
* **`-Os` / `-Oz`**: Loop unrolling is restricted or disabled to minimize code size expansion.

## Why use it / when not to use it

### When to use

* **Hot numerical kernels**: When loop headers and induction variable maintenance incur non-trivial overhead relative to small loop bodies.
* **Exposing ILP**: To provide LLVM's instruction scheduler and vectorizer larger basic blocks for superscalar pipeline saturation.

### When not to use

* **Size-constrained binaries (`-Os` / `-Oz`)**: Duplicating loop bodies increases text segment size.
* **Instruction Cache (I-Cache) pressure**: Excessive unrolling of large loops can cause I-cache misses and worsen performance.
* **High Register Pressure**: Unrolling expands local variable lifespans across duplicated iterations, potentially forcing register spills in the backend register allocator.

## Usage / verification commands

Verify driver translation to CC1:

```bash
clang -O1 -funroll-loops -### -c test.c 2>&1 | grep -E "(-funroll-loops|-mllvm)"
```

Inspect LLVM IR before and after loop unrolling:

```bash
clang -O1 -S -emit-llvm test.c -o baseline.ll
clang -O1 -funroll-loops -S -emit-llvm test.c -o unrolled.ll
diff -u baseline.ll unrolled.ll
```

Inspect generated assembly:

```bash
clang -O1 -funroll-loops -S test.c -o unrolled.s
```

## Adjacent options

* **`-fno-unroll-loops`**: Explicitly disables aggressive loop unrolling in middle-end pipelines.
* **`-freroll-loops`**: Requests that LLVM attempt to reverse unrolled loops into compact loops to reduce code size.
* **`-mllvm -unroll-threshold=N`**: Tunes the internal cost-model threshold for unrolling decisions in LLVM's `LoopUnrollPass`.

## How it works inside Clang

1. **Driver Processing** (`clang/lib/Driver/Driver.cpp`, `clang/include/clang/Driver/Options.td`):
   The driver matches `-funroll-loops` and translates the flag into the `-cc1` flag `-funroll-loops`.
2. **Frontend Option Handlers** (`clang/lib/Frontend/CompilerInvocation.cpp`):
   `CompilerInvocation` parses the CC1 flag into `CodeGenOptions::UnrollLoops = 1`.
3. **Backend Pipeline Creation** (`clang/lib/CodeGen/BackendUtil.cpp`):
   When constructing the LLVM `PassBuilder` optimization pipeline, Clang passes `PipelineTuningOptions::LoopUnrolling = true` to LLVM's pass manager builder.

## Related LLVM Optimizations & Backend Mechanisms

Classification: **A. LLVM IR optimization** (Middle-end PassBuilder optimization pass).

| Mechanism Name | Pipeline Stage | Relationship | Operational Effect |
| :--- | :--- | :--- | :--- |
| `LoopUnrollPass` | LLVM IR PassBuilder | Directly controlled | Duplicates loop body statements and updates phi-nodes and induction variables |
| `LoopFullUnrollPass` | LLVM IR PassBuilder | Directly controlled | Completely removes loop boundaries when trip count is static and under cost threshold |
| `TargetTransformInfo` (TTI) | Target Analysis | Backend mechanism | Provides architecture-specific loop unrolling cost models and vectorization limits |
| `ScalarEvolution` (SCEV) | LLVM IR Analysis | Indirectly affected | Evaluates loop bounds and trip counts to determine unroll eligibility |

Verify pass execution using `opt`:

