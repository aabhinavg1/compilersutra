## At a glance

| Attribute | Details |
| :--- | :--- |
| **Architecture** | Target-independent IR policy — profitability still uses target TTI cost models |
| **Category** | Code Generation / mid-end loop unrolling — not a backend ABI knob |
| **Pipeline** | Driver → cc1 `-funroll-loops` → `CodeGenOpts.UnrollLoops` → PassBuilder `LoopUnrolling` → LoopUnrollPass |
| **Compiler** | Clang (C/C++); CC1Option; FlangOption / FC1Option visibility in Options.td |
| **Optimization Level** | Default `UnrollLoops` is **on** when `OptimizationLevel > 1` (`-O2`+); **off** at `-O0`/`-O1` unless you pass `-funroll-loops` |
| **Risk Level** | Low correctness risk; code-size / I-cache / register-pressure impact can be large |

**In one sentence:** `-funroll-loops` asks Clang to set `CodeGenOptions::UnrollLoops`, which turns on PassBuilder loop-unrolling; the unroller still applies cost heuristics and may leave some loops rolled.

---

## What this flag actually does

On modern Clang (verified with Ubuntu clang 18.1.3, triple `x86_64-pc-linux-gnu`):

1. **Driver** — `Args.AddLastArg(..., OPT_funroll_loops, OPT_fno_unroll_loops)` forwards the **last** of those spellings to cc1 when present. At default `-O2`, `-###` often shows **neither** spelling — the default is applied inside CompilerInvocation from the optimization level, not by injecting `-funroll-loops` into the cc1 command line.
2. **CC1 / CodeGenOptions** — `UnrollLoops = Args.hasFlag(OPT_funroll_loops, OPT_fno_unroll_loops, OptimizationLevel > 1)` ([CompilerInvocation.cpp @ llvmorg-18.1.3](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/lib/Frontend/CompilerInvocation.cpp)).
3. **Pass pipeline** — `BackendUtil` sets `PipelineTuningOptions::LoopUnrolling` (and `LoopInterleaving`) from `CodeGenOpts.UnrollLoops`.
4. **LoopUnrollPass / LoopFullUnrollPass** — may partially, runtime-, or fully unroll when trip count + TTI cost allow. This flag is **not** “always fully unroll every loop.”

:::caution
`-funroll-loops` is not `-fvectorize`, not `-O3`, and not a guarantee of full unroll. `-mllvm -unroll-threshold=` is a separate internal knob. Size modes (`-Os`/`-Oz`) still interact with cost models even when `UnrollLoops` is true.
:::

### Option map and precedence

| Flag | Role |
| :--- | :--- |
| `-funroll-loops` | Prefer enabling `CodeGenOptions::UnrollLoops` |
| `-fno-unroll-loops` | Prefer disabling loop unrolling (`UnrollLoops = false`) |
| `-freroll-loops` | Separate flag: try to reroll previously unrolled patterns |
| `-mllvm -unroll-threshold=N` | Internal LLVM cost threshold (not a driver `-f` flag) |

**Precedence:** among `-funroll-loops` / `-fno-unroll-loops`, the last on the command line wins (`hasFlag` / `AddLastArg`). If neither appears, the default is `OptimizationLevel > 1`.

## Defaults by optimization level (which `-O` introduces it)

Verified from source (`llvmorg-18.1.3`) and experimentally on Ubuntu clang 18.1.3:

| Last `-O` | Default `CodeGenOpts.UnrollLoops` | Driver shows `-funroll-loops` in `-###`? |
| :--- | :--- | :--- |
| (none) / `-O0` | **off** (`OptLevel` 0) | only if you pass `-funroll-loops` |
| `-O1` | **off** | only if you pass `-funroll-loops` |
| **`-O2` / `-O3` / `-Ofast`** | **on** (`OptLevel > 1`) | usually **no** — default is implicit |
| `-Os` / `-Oz` | **on** at CodeGenOpts when OptLevel > 1 (clang 18.1.3) | size cost models may still refuse profitable unroll |

**Which optimization introduces it?** On this baseline, **`-O2` is the first standard numeric level** where `UnrollLoops` defaults to true (`OptimizationLevel > 1`). Pass `-funroll-loops` at `-O1` to force the same knob on; pass `-fno-unroll-loops` at `-O2`+ to force it off.

:::note
Older Clang (present by 3.3–3.8) also gated the default with `!OptimizeSize`, so size opts defaulted `UnrollLoops` off. That gate is **gone** by llvmorg-3.9.0+ (see version history). Always verify your version.
:::

:::important
Do not confuse “default UnrollLoops true” with “`-###` prints `-funroll-loops`.” Check both `clang -###` and whether LoopUnroll actually changed IR/asm for your loop.
:::

## Minimal realistic example

<SourceCode
  file="unroll.c"
  flag="-funroll-loops"
  language="c"
  code={`void scale4(float *restrict out, const float *restrict in) {
  for (int i = 0; i < 4; ++i)
    out[i] = in[i] * 2.0f;
}`}
  note="Fixed trip count 4 — easy full-unroll candidate at -O1 -funroll-loops. At -O2 the same loop may vectorize instead; use -fno-vectorize if you want to isolate unrolling."

```bash
clang -O1 -S unroll.c -o rolled.s
clang -O1 -funroll-loops -S unroll.c -o unrolled.s
clang -### -O1 -funroll-loops -c unroll.c 2>&1 | tr ' ' '\n' | grep unroll
```

## Why use it / when not to use it

### When to use

- Force unrolling at `-O0`/`-O1` for experiments or tiny fixed-trip kernels.
- Compare rolled vs unrolled asm/IR without bumping the whole `-O` level.

### When not to use

- Size-constrained builds where duplication hurts (`-Os`/`-Oz` workflows) — measure; consider `-fno-unroll-loops`.
- Assuming it overrides profitability — large bodies / unknown trip counts may stay rolled.
- As a substitute for `-O3` or for enabling vectorization.

---

## Performance impact

Unrolling can remove loop-branch overhead and expose ILP, but it grows code and can increase register pressure / I-cache misses. Measure with [CompilerSutraPerf](/docs/project/compilersutra-perf/) ([PyPI](https://pypi.org/project/compilersutra-perf/)) on your kernel; no `PerfReport` numbers are published on this page yet.

## Compatibility

| Layer | Behavior |
| :--- | :--- |
| **Clang driver** | Forwards last of `-funroll-loops` / `-fno-unroll-loops` to cc1 |
| **CC1** | Sets `CodeGenOptions::UnrollLoops` |
| **GCC** | Related `-funroll-loops` spelling exists; heuristics differ — do not assume identical asm |
| **Flang** | Options.td marks Flang/FC1 visibility; verify Fortran defaults separately |

## Usage example

```bash
# Force unroll at -O1
clang -O1 -funroll-loops -S kernel.c -o - | less

# Disable unroll at -O2
clang -O2 -fno-unroll-loops -S -emit-llvm kernel.c -o - | less

# See whether the driver spelled the flag (may be empty at default -O2)
clang -### -O2 -c kernel.c 2>&1 | tr ' ' '\n' | grep unroll || echo "no explicit unroll flag on cc1"
```

## Adjacent options

- `-fno-unroll-loops` — force `UnrollLoops = false`.
- `-freroll-loops` — separate mid-end reroll request.
- `-fno-vectorize` / `-fvectorize` — loop vectorization; orthogonal but often confuses O2 asm diffs.
- `-mllvm -unroll-threshold=N` — internal cost threshold (escape hatch; not a stable driver UI).

## How it works inside Clang

```mermaid
flowchart LR
  A["Driver<br/>-f(no-)unroll-loops"] --> B["CC1"]
  B --> C["CodeGenOpts.UnrollLoops<br/>default OptLevel > 1"]
  C --> D["PassBuilder PTO.LoopUnrolling"]
  D --> E["LoopUnrollPass / FullUnroll"]
  E --> F["Expanded or rolled IR"]
  F --> G["Target backend"]
```

| Pipeline stage | Implementation detail |
| :--- | :--- |
| **Options.td** | `funroll_loops` / `fno_unroll_loops` — [llvmorg-18.1.3 Options.td](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/include/clang/Driver/Options.td) |
| **Driver** | `AddLastArg` in [Clang.cpp](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/clang/lib/Driver/ToolChains/Clang.cpp) |
| **Invocation** | `UnrollLoops = hasFlag(..., OptimizationLevel > 1)` |
| **BackendUtil** | `PTO.LoopUnrolling = CodeGenOpts.UnrollLoops` |
| **LLVM** | `LoopUnrollPass` / full-unroll variants + TTI |

## Related LLVM Optimizations & Backend Mechanisms

| Mechanism | Stage | Relationship | Effect |
| :--- | :--- | :--- | :--- |
| `CodeGenOptions::UnrollLoops` | CC1 / CodeGen | Directly controlled | Master enable for PassBuilder loop unrolling |
| `PipelineTuningOptions::LoopUnrolling` | PassBuilder | Directly controlled | Schedules unroll-related passes |
| `LoopUnrollPass` / full unroll | Mid-end | Directly controlled | Transforms eligible loops |
| `TargetTransformInfo` | Analysis / target | Backend mechanism | Cost model / target limits |
| `LoopVectorize` | Mid-end | Related mechanism | Separate flag family (`-f(no-)vectorize`) |
| Sanitizer instrumentation | Instrumentation | No direct pass | Not controlled by this flag |

#### How to verify

```bash
clang -O1 -funroll-loops -### -c t.c 2>&1 | tr ' ' '\n' | grep unroll
clang -O1 -S t.c -o rolled.s
clang -O1 -funroll-loops -S t.c -o unrolled.s
diff -u rolled.s unrolled.s | head
```
