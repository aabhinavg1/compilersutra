## What this flag actually does

-g asks Clang to emit debug information, normally DWARF on Unix-like targets and CodeView in relevant Windows configurations. It does not disable optimization and does not guarantee every source variable remains observable.

## Why use it / when not to use it

Use it when the debug information behavior matches the build contract. Do not enable it selectively across mutually dependent translation units when it changes preprocessing, language rules, ABI expectations, or runtime instrumentation. Verify the effect with the exact compiler and target used by CI.

:::caution
This option does not repair invalid source, undefined behavior, data races, or an inconsistent build contract. It only changes the compiler mechanism described above.
:::

## Performance impact

`-g` adds debug information. Optimized runtime is often nearly unchanged; binary size and link time usually grow. Measure both when debug info is part of a release-adjacent build.

## Usage example

~~~bash
clang++ -g -O0 -fno-omit-frame-pointer main.cpp -o app
clang++ -g -### -c main.cpp
~~~

## Adjacent options

Use the inverse or sibling spelling where available, and inspect the generated driver command with -###. Related controls include -O levels, -g, -I/-isystem, -D/-U, -fsanitize-recover, and target or linker options as appropriate.

## How it works inside Clang

### Implementation

| Stage | Source and implementation | What happens |
| --- | --- | --- |
| Options.td | [Options.td](https://github.com/llvm/llvm-project/blob/main/clang/include/clang/Options/Options.td) | Declares the debug-information option group and debug format options; TableGen emits the option identifiers and marshalling records. |
| Driver parsing | [Clang.cpp](https://github.com/llvm/llvm-project/blob/main/clang/lib/Driver/ToolChains/Clang.cpp) | The driver claims the debug option group and forwards the selected debug settings to `cc1`; it does not turn optimization off. |
| Invocation setup | [CompilerInvocation.cpp](https://github.com/llvm/llvm-project/blob/main/clang/lib/Frontend/CompilerInvocation.cpp) | Generated option marshalling records the debug format and level in `CodeGenOptions` and `DebugOptions`. |
| Code generation | [CGDebugInfo.cpp](https://github.com/llvm/llvm-project/blob/main/clang/lib/CodeGen/CGDebugInfo.cpp) | Clang creates `DICompileUnit`, type, scope, and location metadata while lowering source constructs. |
| LLVM IR / object | [LLVM SourceLevelDebugging](https://llvm.org/docs/SourceLevelDebugging.html) | LLVM carries `DI*` metadata; the target backend lowers it into DWARF or CodeView sections. |
| Linker / debugger | [Clang source-level debugging](https://clang.llvm.org/docs/SourceLevelDebugging.html) | The linker preserves or combines debug sections; LLDB/GDB consume the resulting format. |

~~~mermaid
flowchart LR
 A["-g"] --> B["Options.td"] --> C["Clang driver"] --> D["CompilerInvocation"] --> E["frontend / CodeGenOptions"] --> F["LLVM IR or diagnostics"] --> G["backend / linker"]
~~~

The -g spelling is handled by the driver and translated into frontend, diagnostic, target, IR, or runtime state as shown above. LLVM and the linker consume the resulting representation; they do not generally parse the original user-facing spelling.
