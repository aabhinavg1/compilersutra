## What this flag actually does

The `-fno-rtti` flag instructs the Clang frontend to disable language support for C++ Run-Time Type Information (RTTI). When set, Clang sets the internal option `LangOpts.RTTI = 0` and `LangOpts.RTTIData = 0`.

This alters frontend analysis and LLVM IR code generation in three distinct ways:

1. **Language Construct Enforcement**: Usage of `dynamic_cast` (when downcasting or cross-casting polymorphic types) or `typeid` on expressions with dynamic type causes the frontend to emit a hard diagnostic error (`error: 'dynamic_cast' not allowed with -fno-rtti`).
2. **Vtable RTTI Pointer Nullification**: Under the Itanium C++ ABI, virtual function tables contain an RTTI pointer slot positioned immediately before the virtual function pointers (offset `-8` on 64-bit architectures). With `-fno-rtti`, Clang sets this vtable slot to `0` (`i8* null`) instead of pointing to a `type_info` structure global.
3. **Type Info Symbol Omission**: Clang entirely suppresses emission of `typeid` metadata objects (`_ZTIN...` typeinfo symbols and `_TSN...` typeinfo name strings in Itanium ABI).

:::note Exception Handling Interaction
Disabling RTTI (`-fno-rtti`) does **not** automatically disable C++ exceptions (`-fexceptions`). However, exception matching in thrown objects (`catch (const MyException& e)`) relies on exception type descriptors emitted by the personality function. Under `-fno-rtti`, Clang still generates minimal C++ exception type descriptors required for exception unwinding unless `-fno-exceptions` is also specified.
:::

## Minimal realistic example

Consider a polymorphic base class `Base` and derived class `Derived`:

<SourceCode language="cpp" code={`// example.cpp
class Base {
public:
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    void work() {}
};

const void* get_rtti_ptr(Base* b) {
    // Under -fno-rtti, using dynamic_cast or typeid triggers compile error:
    // dynamic_cast<Derived*>(b); // Error if uncommented
    return nullptr;
}
`} />

Compiling with `-frtti` vs `-fno-rtti` changes the vtable declaration emitted in LLVM IR:

```llvm
; Default (-frtti):
; Offset -8 points to the global _ZTI4Base (type_info for Base)
@_ZTV4Base = unnamed_addr constant { [3 x i8*] } { [3 x i8*] [
    i8* null,
    i8* bitcast ({ i8*, i8* }* @_ZTI4Base to i8*),
    i8* bitcast (void (%class.Base*)* @_ZN4BaseD2Ev to i8*)
] }, align 8

; With -fno-rtti:
; Offset -8 is set to null pointer (0)
@_ZTV4Base = unnamed_addr constant { [3 x i8*] } { [3 x i8*] [
    i8* null,
    i8* null,
    i8* bitcast (void (%class.Base*)* @_ZN4BaseD2Ev to i8*)
] }, align 8
```

## Why use it / when not to use it

### Why use `-fno-rtti`
* **Binary Size Reduction**: Large C++ codebases with thousands of polymorphic classes incur non-trivial `.rodata` overhead from type names (`_ZTS...`) and `type_info` structures (`_ZTI...`). Disabling RTTI strips this static overhead.
* **Embedded & Bare-Metal Targets**: Embedded systems or microcontrollers with constrained flash memory frequently strip RTTI to save space.
* **Custom Type Systems**: High-performance C++ engines (such as LLVM itself, Game Engines, or Chromium) implement custom, low-overhead RTTI mechanisms (e.g., `isa<>`, `cast<>`, `dyn_cast<>` via enum class discriminators) that do not require runtime dynamic dispatch or string tables.

### When NOT to use it
* **Dependency on Standard RTTI**: Libraries that rely on `std::any`, `std::bad_cast`, `dynamic_cast`, or `typeid` will fail to compile.
* **Interoperability with RTTI-enabled Shared Libraries**: Mixing C++ objects compiled with `-fno-rtti` and `-frtti` across boundary interfaces can lead to ODR violation warnings or runtime dynamic casting failures when crossing library boundaries.

---

## Performance impact

Qualitatively, `-fno-rtti` yields:
1. **Binary Size**: Reduction in `.rodata` footprint. In LLVM-scale projects, disabling standard RTTI eliminates megabytes of mangled type name string tables and COMDAT relocations.
2. **Instruction Cache (i-cache) & Memory**: Omitting type metadata improves cache locality for vtable accesses since vtables no longer reference scattered `type_info` metadata symbols.
3. **Execution Time**: Modern C++ Virtual function call overhead is unchanged; however, avoiding dynamic type check operations replacing `dynamic_cast` with custom enum class discriminators avoids indirect calls and library helper invocations (`__dynamic_cast`).

## Compatibility table

| Environment / Standard | Compatibility | Notes |
| :--- | :--- | :--- |
| **Itanium C++ ABI** | Fully Supported | Nullifies offset `-8` slot in vtable; omits `_ZTI` / `_ZTS` symbols. |
| **MSVC / Windows ABI** | Fully Supported | Disables `Complete Object Locator` metadata and `??_R...` type descriptors. |
| **C++11 / 14 / 17 / 20 / 23** | Fully Supported | Dialect independent. |
| **Clang / GCC / MSVC** | Compatible Flag | Supported across Clang (`-fno-rtti`), GCC (`-fno-rtti`), and MSVC (`/GR-`). |

## Usage example

Pass `-fno-rtti` directly to `clang++` during compilation:

```bash
# Compile single translation unit without RTTI
clang++ -O2 -fno-rtti -c module.cpp -o module.o

# Inspect vtable symbol references with llvm-readelf
llvm-readelf -s module.o | grep _ZTI

# Disable both RTTI and C++ exceptions for embedded targets
clang++ -O3 -fno-rtti -fno-exceptions -target armv7m-none-eabi -c embedded.cpp
```

## Adjacent options

* `-frtti`: Re-enables RTTI generation (default behavior).
* `-fno-rtti-data`: Advanced option that generates type_info structures for `typeid` expressions but omits vtable RTTI pointers.
* `-fno-exceptions`: Disables C++ exception handling (`try`/`catch`/`throw`), commonly paired with `-fno-rtti` in embedded builds.
* `-fvisibility-inlines-hidden`: Frequently used alongside `-fno-rtti` to reduce binary symbol footprint.

## How it works inside Clang

| Pipeline Stage | Module / File | Mechanism |
| :--- | :--- | :--- |
| **Driver Options** | `clang/include/clang/Driver/Options.td` | Option `-fno-rtti` maps to `LangOpts.RTTI = 0` and `LangOpts.RTTIData = 0`. |
| **Frontend Sema** | `clang/lib/Sema/SemaExprCXX.cpp` | `BuildCXXDynamicCast` and `BuildCXXTypeId` check `getLangOpts().RTTI`; raise diagnostic error if false. |
| **AST / Type Info** | `clang/lib/AST/ASTContext.cpp` | Suppresses `getTypeInfo` layout metadata for dynamic type lookup tables. |
| **CodeGen / VTable** | `clang/lib/CodeGen/CGVTables.cpp` | Inspects `LangOpts.RTTI`. Emits null pointers for vtable RTTI slots in `ItaniumCXXABI.cpp` and `MicrosoftCXXABI.cpp`. |
